# Тренажер — платформа подготовки к экзамену

React + Vite + Tailwind. Сайт: главная, список пробников и их
прохождение, информация об экзамене, о проекте, личный словарь,
вход/регистрация — и черновая админ-панель поверх Supabase.

## Структура проекта

```
src/
  components/        # Header, Footer, TestCard, FilterSelect, HighlightableText,
                      # QuestionNavGrid, RichText, RichSelectableContent, CalloutBox,
                      # AddWordModal, RequireAuth, NavDropdown, HeroIllustration...
  components/admin/  # AdminQuestionForm, AdminPassageForm, RichTextEditor
  pages/              # HomePage, PracticeTestsPage, TestDetailPage, TestTakingPage,
                       # ExamInfoPage, AboutPage, VocabularyPage, BookPage,
                       # LoginPage, StubPage
  pages/admin/        # AdminLayout, AdminTestsListPage, AdminTestFormPage,
                       # AdminBookPage, AdminBookChapterPage, AdminBookSubchapterPage,
                       # AdminCategoriesPage
  data/
    seed.js           # демо-данные для локального режима (без Supabase)
    translations.js   # перевод через MyMemory API + мини-глоссарий
  lib/
    supabaseClient.js  # клиент Supabase (null, пока не задан .env)
    authContext.jsx      # сессия входа (Supabase Auth) — useAuth(), isAdmin
    localStore.js       # CRUD поверх localStorage — реальное хранилище
                         # для админки, пока Supabase не подключен
    localBookHighlights.js # локальный фолбэк для выделений в книге
                            # (Supabase не настроен или чтение не залогинено)
    data.js              # единая точка доступа к данным — сама решает,
                          # брать данные из Supabase или из localStore
    markdownLite.js        # разбор **жирного**, *курсива* и [[callout:..]]
                            # сносок из текста, вводимого через RichTextEditor
    vocabulary.js         # личный словарь пользователя (localStorage)
    steps.js               # сборка последовательности вопросов+вступлений
                            # и группировка по категориям для теста
    originality.js          # общий список "официальный/неофициальный"
    time.js                  # форматирование таймера
supabase/
  full-reset.sql            # снести и пересоздать все таблицы + категория + Пробник 2026
  probnik-2026-questions.sql  # 26 вопросов для Пробника 2026 (запускать после full-reset.sql)
  add-points-and-pdf.sql     # добавляет колонки points (баллы) и pdf_url без потери данных
  add-pro-access.sql         # добавляет колонку is_pro (пробник только для PRO) без потери данных
  add-book.sql               # добавляет главы книги и таблицу выделений/заметок
  add-test-order.sql         # порядок пробников (перетаскивание в админке)
  add-test-sections.sql      # разделы-подзаголовки внутри вкладки ("Глава 1"...)
  admin-policies.sql         # роль admin в app_metadata + запись в контент только админу
  admin-users.sql            # функции для вкладки «Пользователи» (список, выдача PRO)
  add-progress.sql           # колонки user_progress для страницы «Мой прогресс»
  auth-policies.sql          # устарел, заменён admin-policies.sql
```

Идея: компоненты дергают функции из `src/lib/data.js` и не знают,
откуда реально приходят данные. Пока `.env` не заполнен — работает
демо-набор из `seed.js`, приложение полностью рабочее. Как только
подключишь Supabase — переключение произойдёт само, без правок в
страницах.

## 1. Запуск локально

Нужен Node.js 20+.

```bash
npm install
npm run dev
```

Откроется на `http://localhost:5173`.

Тесты логики (подсчёт баллов, порядок вопросов и вступлений):

```bash
npm test
```

## 2. Подключение базы данных (Supabase, бесплатно)

GitHub Pages — это только статический хостинг, сервера и базы там
нет. Supabase — облачный PostgreSQL с готовым API, бесплатного тарифа
достаточно с большим запасом для такого проекта. Ниже — подробно, шаг
за шагом, без предположений, что ты уже с этим работал.

### Шаг 1. Создать аккаунт и проект

1. Открой [supabase.com](https://supabase.com) → **Start your project**
   → войди через GitHub или email.
2. **New project**: впиши имя (например, `exam-prep`), придумай и
   сохрани где-нибудь **Database Password** (понадобится редко, но
   если потеряешь — придётся сбрасывать), выбери регион поближе
   (например, Frankfurt — `eu-central-1`), тариф — **Free**.
3. Нажми **Create new project** и подожди 1–2 минуты, пока Supabase
   поднимет базу — будет крутиться индикатор загрузки.

### Шаг 2. Создать таблицы и загрузить «Пробник 2026»

1. В левом меню открой **SQL Editor** → **New query**.
2. Открой файл `supabase/full-reset.sql` из этого проекта, скопируй весь
   его текст, вставь в редактор в Supabase и нажми **Run** (или
   `Ctrl+Enter`). Это сносит и пересоздаёт **все** таблицы приложения
   (`categories`, `practice_tests`, `questions`, `passages`,
   `user_progress`, `user_vocabulary`) под актуальную структуру — если
   там были старые данные от прошлых версий, они удалятся. Тут же
   этот файл создаёт категорию «Пробники» и сам «Пробник 2026»
   (пока без вопросов).

   Аутентификацию (зарегистрированных пользователей) этот файл не
   трогает — таблица `auth.users` управляется самим Supabase, а не
   этой схемой. Если хочешь почистить и её — это вручную, в
   **Authentication → Users** в дэшборде.
3. Новый **New query** → вставь `supabase/probnik-2026-questions.sql`
   → **Run**. Это добавит все 26 вопросов в «Пробник 2026»,
   разложенные по трём категориям (Понимание экономики / Понимание
   немецкого текста / Математика) с правильными ответами.
4. Новый **New query** → вставь `supabase/add-points-and-pdf.sql` →
   **Run**. Это добавляет колонку `points` (баллы за вопрос, для
   системы частичной оценки) и `pdf_url` (PDF-файл пробника) — без
   удаления уже загруженных данных, можно выполнять в любой момент.
5. Новый **New query** → вставь `supabase/add-pro-access.sql` → **Run**.
   Это добавляет колонку `is_pro` (пробник только для подписки PRO или
   для всех) — без удаления данных, все существующие пробники останутся
   доступными всем. Без этой колонки список пробников из Supabase не
   загрузится (запрос её ожидает).
   Так же — `supabase/add-test-order.sql`: добавляет колонку `sort_order`
   (порядок пробников, меняется перетаскиванием в админке). Без неё список
   пробников из Supabase тоже не загрузится.
6. Новый **New query** → вставь `supabase/add-book.sql` → **Run**. Это
   создаёт таблицы под раздел «Книга»: главы (`book_chapters`), подглавы
   (`book_subchapters`), страницы внутри подглавы (`book_pages` — текст +
   опционально фото/ссылка на видео) и личные выделения/заметки читателей
   (`book_highlights`, привязаны к странице и к аккаунту, у каждого свои).
   Если запускаешь этот файл повторно (например, после более ранней
   плоской версии) — он сам сносит старые таблицы книги и создаёт заново,
   это ожидаемо и безопасно, пока реальный контент книги ещё не занесён.
7. Проверить результат можно в **Table Editor** — в `practice_tests`
   должна быть одна строка «Пробник 2026», в `questions` — 26 строк.

### Шаг 3. Получить ключи API

1. **Project Settings** (значок шестерёнки внизу слева) → **API**.
2. Скопируй два значения: **Project URL** и **anon public** ключ
   (длинная строка под «Project API keys»). Ключ `service_role`
   рядом — не трогай, его нельзя использовать во фронтенде.

### Шаг 4. Подставить ключи в проект

1. В папке проекта скопируй `.env.example` в `.env`:
   ```bash
   cp .env.example .env
   ```
2. Открой `.env` и вставь свои значения:
   ```
   VITE_SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co
   VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
   ```
3. Перезапусти локальный сервер, если он был запущен:
   ```bash
   npm run dev
   ```
4. Проверка: зайди в `/admin/probniki`, добавь тестовый пробник —
   он должен тут же появиться в Supabase (**Table Editor** →
   `practice_tests`). Значит подключение работает.

### Важно про безопасность на этом этапе

В `full-reset.sql` сейчас сознательно разрешена запись (добавление,
редактирование, удаление) в `categories`, `practice_tests` и
`questions` для любого, кто обращается с anon-ключом — а этот ключ
лежит прямо в коде фронтенда и виден всем, кто открывает сайт (через
вкладку Network в браузере, например). Это осознанный компромисс: ты
попросил админку без ролей и доступов, чтобы просто быстро наполнять
контент, — так оно и работает. Но это значит, что теоретически
кто угодно, кто найдёт твой URL и ключ, может изменить или удалить
твои пробники через API.

Пока ты один наполняешь черновой контент — это нормально. Но как
только зарегистрируешься на `/login` — выполни
`supabase/admin-policies.sql` (см. «Защита админки» ниже): после него
писать в контент (пробники, вопросы, тексты, категории, книгу) может
только аккаунт с ролью `admin`, а читать — по-прежнему все.

### Что не переносится автоматически

Если ты что-то добавлял через админку в режиме localStorage (до
подключения Supabase) — это осталось только в том браузере и **не**
переедет в базу само. Если это было немного — свериться и добавить
руками через **Table Editor** в Supabase, либо просто занести заново
через админку уже в режиме Supabase.

Когда дойдём до логинов учеников и сохранения прогресса — включим
Supabase Auth (email/password или магическую ссылку) полностью; форма
входа уже есть на `/login`, схема под `user_progress` уже в
`full-reset.sql`.

## 3. Админ-панель

Пункт «Админка» в шапке ведёт на `/admin` и виден только аккаунту с
ролью `admin` (см. «Защита админки»).

- **Пробники** (`/admin/probniki`) — список, создание, редактирование,
  удаление. У каждого пробника: название, краткое и полное описание
  (с простым форматированием — кнопка «Жирный» и абзацы по строкам),
  год/время на выполнение, оригинальность (официальный/неофициальный),
  закрепление (показывается первым в списке — переключается прямо на
  карточке пробника иконкой-булавкой), и необязательный PDF-файл
  самого пробника (загружается файлом, отдаётся студенту по кнопке
  «Скачать пробник в PDF» на странице пробника — пока файл не
  загружен, кнопка неактивна). Сам файл (base64, может весить
  мегабайты) нигде не подгружается заранее — ни в списке пробников, ни
  на странице пробника: только по клику на «Скачать», отдельным
  запросом. Иначе список/страница ощутимо тормозят, стоит один такой
  файл добавить.
- Порядок пробников меняется перетаскиванием строк в `/admin/probniki`
  (за значок ⋮⋮ слева) — в том же порядке они показываются в `/probniki`.
  Закреплённые всегда идут первыми, поэтому переставлять можно внутри
  группы: закреплённые между собой, остальные между собой.
- В списке пробников у каждой карточки рядом с «Редактировать» и
  «Удалить» есть кнопка доступа: **«Для всех»** / **«Только PRO»** —
  клик переключает флаг `is_pro` у пробника. Как это выглядит для
  пользователей и как выдать PRO — см. «PRO-пробники» ниже.
- Внутри редактирования пробника — **управление вопросами**: текст
  вопроса, варианты ответа (отмечаешь верные галочками, вариантов может
  быть сколько угодно), категория вопроса (текстом, например
  «Математика» — на неё завязана группировка в левом меню теста),
  баллы за вопрос (для частичной системы оценки — см. ниже),
  необязательное фото (загружается файлом и хранится прямо в вопросе
  как base64 — для большого количества/крупных фото в будущем разумнее
  переехать на Supabase Storage), и объяснение, которое показывается
  после ответа. Порядок вопросов стабильный — редактирование вопроса
  больше не переставляет его в конец списка.
- Там же — **«Тексты и вступления»**: блок, который либо показывается
  один раз перед первым вопросом категории («вступление» — например,
  список формул для математики), либо закрепляется рядом с вопросами
  всю категорию («текст для чтения» — например, немецкий текст; можно
  завести несколько таких текстов на категорию, каждый со своего
  вопроса — переключение между ними произойдёт автоматически по мере
  прохождения).
- **Категории** (`/admin/categories`) — список категорий пробников
  (сейчас только «Пробники»; это категория самого пробника, не путать
  с категорией вопроса).

Пока Supabase не подключен, всё это по-настоящему сохраняется в
localStorage браузера (см. `src/lib/localStore.js`) — данные переживут
перезагрузку страницы, но живут только в этом браузере/устройстве.
Как только заполнишь `.env` из шага 2 — `src/lib/data.js` сам
переключит чтение/запись на Supabase, менять компоненты не придётся.

### Прохождение теста

- Таймер в левом меню запускается сам, как только открыт тест; кнопка
  паузы рядом с ним.
- Если у вопросов заданы категории — левое меню группирует их по
  разделам с заголовками; если у раздела есть вступление, рядом с
  заголовком появляется значок (i) для перехода к нему.
- Ответ всегда можно выбрать в нескольких вариантах, независимо от
  того, сколько верных ответов у вопроса.
- Перевести слово/фразу и добавить слово в словарь можно как в тексте
  вопроса, так и в тексте каждого варианта ответа, и в закреплённом
  тексте для чтения — выдели текст мышкой, во всплывающем меню сначала
  выбери действие, и только «Выделить» проставит жёлтый маркер.
  «Добавить в словарь» открывает то же модальное окно, что и на
  странице «Словарь», со словом уже подставленным — сразу можно
  добавить перевод, пример и категорию, а не просто сохранить голое
  слово.
- Оценка вопросов с несколькими правильными ответами — с частичными
  баллами: если правильный ответ один — всё или ничего; если верных
  ответов несколько — за каждый отмеченный верный начисляется `max/r`,
  за каждый отмеченный неверный списывается `max/f` (где `r`/`f` — число
  верных/неверных вариантов), а если неверный вариант всего один — штраф
  в два раза мягче (`max/(2f)`). Итог не может быть отрицательным.
  `max` — баллы за вопрос, задаются в админке (по умолчанию 1).
  Сетка вопросов слева и итог теста показывают статус «частично верно»
  отдельным (жёлтым) цветом.
- Если нажать «Завершить», не ответив на все вопросы, — переспросит
  подтверждение, можно отменить и вернуться к вопросам.

## 4. Страницы сайта

Меню в шапке: Главная → Пробники → «Моё обучение» (выпадающее —
Книга, Словарь, Мой прогресс) → Об экзамене → О проекте → Админка
(видна только с ролью `admin`, см. «Защита админки» ниже).

- **Главная** (`/`) — краткое описание проекта и кнопки на пробники,
  информацию об экзамене и о проекте, плюс блок-ссылка на статистику
  последнего экзамена.
- **Пробники** (`/probniki`) — список тестов (переехал сюда с `/`).
- **Книга** (`/kniga`) — учебник в виде Глава → Подглава → Страницы, как
  в оглавлении настоящего учебника (например «1. Warum wir
  wirtschaften» → «1.1 Jeder Mensch ist Teil der Wirtschaft» → её
  страницы). Слева — сворачиваемое оглавление (клик по главе
  разворачивает список подглав), справа — текущая страница выбранной
  подглавы с перелистыванием «Назад / Далее». У страницы может быть
  фото и/или ссылка на видео. Выделение текста работает так же, как в
  пробниках (выдели → в попапе выбери действие: перевести / добавить в
  словарь / выделить), плюс здесь ещё можно оставить заметку — клик по
  уже выделенному фрагменту открывает мини-редактор заметки прямо на
  месте. Выделения и заметки привязаны к конкретной странице и
  сохраняются по-настоящему — если человек вошёл в аккаунт, они в
  Supabase и видны с любого устройства; если не вошёл (или Supabase не
  настроен) — сохраняются локально, в этом браузере, с
  баннером-подсказкой войти.
  Наполняется через `/admin/kniga`: сначала создаёшь главу (название +
  необязательный вступительный абзац до первой подглавы — как в
  примере учебника), внутри неё — подглавы, внутри каждой подглавы —
  страницы (текст с лёгким markdown — плюс опционально фото файлом или
  ссылка на видео). В текстовом поле есть кнопки **Жирный** и
  *Курсив* (сначала выделяешь текст мышкой, потом жмёшь), а ещё
  **Сноска** — оборачивает выделенный текст (например, заголовок +
  абзац) в блок с иконкой слева и текстом справа, как в учебнике
  («Was ist das BIP?», «Zahlen, Daten, Fakten…»); иконка выбирается
  рядом с кнопкой (лампочка, лупа, инфо, предупреждение). Сноска не
  центрируется по иконке — если текст выше иконки, оба выравниваются
  по верхнему краю. Сноски не участвуют в выделении/переводе (это
  вспомогательный блок), а вот жирный и курсив внутри самой сноски
  работают. Та же кнопочная панель (жирный/курсив/сноска) доступна и в
  описаниях пробников, и в тексте для чтения (`passages`) — везде, где
  есть `RichTextEditor`.
  Мы намеренно храним книгу как текст по страницам, а не как
  вставленный PDF-файл — так работает быстро, легко на телефоне и
  выделение/перевод/заметки не пришлось городить с нуля под PDF; для
  тех, кому нужна точная вёрстка (формулы, таблицы), позже можно
  добавить отдельную кнопку «Скачать
  оригинал в PDF» по тому же принципу, что уже сделано для пробников.
- **Мой прогресс** (`/progress`) — результаты тестов: сводка (пройдено
  тестов, средний результат, время подготовки, дней подряд), прогресс по
  главам (процент = среднее лучших результатов подглав главы, непройденная
  = 0; по клику — подробно по подглавам), последний тест, «что дальше»,
  «стоит повторить» и словарь. Результат теста сохраняется при нажатии
  «Завершить»: у вошедшего — в `user_progress` (нужен
  `supabase/add-progress.sql`), у гостя — в этом браузере.
- **Словарь** (`/slovar`) — если слов нет, предлагает добавить первое;
  дальше слова показываются списком по категориям (кнопка «Добавить

  (File → Import) и в Quizlet (Import → между термином и определением:
  Tab, между карточками: новая строка) без доработок.
- **Об экзамене** (`/exam-info`) — текстовая страница с оглавлением в
  виде горизонтального меню (Общая информация → Статистика и проходной
  балл → Процесс регистрации → Полезные материалы). Контент сейчас —
  заглушки, наполним позже.
- **О проекте** (`/about`) — тоже пока заглушка.
- **Вход/регистрация** (`/login`) — email и пароль через Supabase Auth.

### Защита админки

Раздел `/admin` требует входа **и** роли `admin` — без сессии Supabase
Auth редиректит на `/login`; если сессия есть, но роли нет, показывает
«Доступ только для администраторов». Без Supabase (`.env` не заполнен)
проверка не включается, чтобы не мешать локальной разработке до его
подключения.

Пункт «Админка» в шапке сайта тоже показывается только пользователям с
этой ролью.

Роль хранится в `app_metadata` пользователя — его меняет только
сервер/админ через SQL. (Раньше роль лежала в `user_metadata`, но его
пользователь может переписать сам через API Supabase — то есть любой
мог объявить себя админом.) Панели управления ролями пока нет, роль
выдаётся через SQL:

1. Зарегистрируйся на `/login` (обычная регистрация).
2. В Supabase **SQL Editor** выполни, подставив свой email:
   ```sql
   update auth.users
   set raw_app_meta_data = raw_app_meta_data || '{"role": "admin"}'
   where email = 'твой@email';
   ```
3. Выполни `supabase/admin-policies.sql` — он закрывает запись в базу
   для всех, кроме админа (это защищает уже не только интерфейс, но и
   прямые запросы к API с anon-ключом). Он же переносит роль из старого
   места (`user_metadata`), если ты выдавал её раньше, и в конце
   показывает, у кого сейчас роль admin — там должен быть только ты.
4. Выйди и войди на сайте заново — роль попадает в токен входа только
   при новом входе. Теперь в шапке появится «Админка».

Если после этого изменение в админке не сохраняется — сайт покажет
сообщение «нет прав на запись»: значит роль не выдана или ты не
перезашёл.

### PRO-пробники

Если у пробника включено «Только PRO», то для гостей и для вошедших
без PRO:

- карточка в `/probniki` серая, сверху плашка «Доступно только в
  PRO-версии», кнопка «Подробнее» вместо «Начать тест»;
- на странице пробника (и по прямой ссылке на `/probniki/<id>/exam`)
  вместо описания и теста — экран «Нужна PRO-версия» с кнопкой
  «Оформить PRO» (ведёт на `/pro`, пока заглушка) и, для гостей,
  ссылкой «Войти».

Админ (роль `admin`) видит все пробники как обычно.

Оплаты пока нет — PRO выдаётся вручную, во вкладке **Пользователи**
админки (`/admin/users`): там список всех зарегистрированных (поиск по
email, фильтр «PRO / без PRO») и кнопка «Выдать PRO» / «PRO · забрать»
у каждого. Перед первым использованием один раз выполни
`supabase/admin-users.sql` в SQL Editor (после `admin-policies.sql`) —
он создаёт две SQL-функции, через которые админка читает пользователей
и меняет им PRO; обе сами проверяют, что их вызывает админ.

Изменение доходит до пользователя при его следующем входе или в течение
часа — когда Supabase сам обновит его сессию.

То же самое вручную, в Supabase **SQL Editor**:

```sql
update auth.users
set raw_app_meta_data = raw_app_meta_data || '{"plan": "pro"}'
where email = 'user@example.com';
```

Забрать PRO — то же самое с `'{"plan": "free"}'`. Пользователю нужно
перезайти (выйти → войти), чтобы изменение подхватилось.

Флаг хранится в `app_metadata` (как и роль admin), а не в
`user_metadata`: `user_metadata` пользователь может изменить сам через
API Supabase, `app_metadata` — только сервер/админ.

Важно: это ограничение только в интерфейсе. Сами вопросы PRO-пробника
по-прежнему отдаются из базы любому, кто обратится к API напрямую с
anon-ключом. Настоящую защиту (RLS-политика на `questions`, проверяющая
`plan` в JWT) стоит добавить вместе с оплатой.

## 5. Деплой на GitHub Pages

### Вариант А — автоматически через GitHub Actions (рекомендуется)

В репозитории уже лежит `.github/workflows/deploy.yml`.

1. Создай репозиторий на GitHub и запушь туда проект:
   ```bash
   git init
   git add .
   git commit -m "Первая версия: страница Пробники"
   git branch -M main
   git remote add origin https://github.com/<твой-юзернейм>/<репозиторий>.git
   git push -u origin main
   ```
2. В настройках репозитория: **Settings → Pages → Source** — выбери
   **GitHub Actions**.
3. Если используешь Supabase — добавь секреты: **Settings → Secrets
   and variables → Actions** → `VITE_SUPABASE_URL` и
   `VITE_SUPABASE_ANON_KEY`.
4. Открой `vite.config.js` и поменяй `base` на `/<имя-репозитория>/`
   (уже стоит `/exam-prep-app/` — если репозиторий называется иначе,
   поправь).
5. При следующем `git push` в `main` сайт задеплоится сам. Ссылка
   появится в **Settings → Pages**.

### Вариант Б — вручную, одной командой

```bash
npm run deploy
```

Это соберёт проект и запушит `dist/` в ветку `gh-pages` (пакет
`gh-pages` уже в devDependencies). В настройках **Pages** выбери
источник — ветку `gh-pages`.
